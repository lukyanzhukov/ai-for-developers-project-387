Запуск макета:

```bash
pnpm exec vite
```

Состояния переключаются кнопками внизу. Все данные вымышленные, API не вызывается.

Переснять скриншоты одной командой:


## Согласованное поведение

1. Пустой выбор типов означает «Все типы»; отдельной кнопки сброса нет, все выбранные типы удаляются крестиками пилюль или общим крестиком `MultiSelect`.
2. Варианты типов берутся из существующего `GET /api/meeting-types`. Новые API-параметры не нужны.
3. Тип считается активным, если в текущем `BookingList` есть хотя бы одна его встреча. Внутри активных и недоступных групп типы отсортированы по названию.
4. Фильтрация работает и в списке, и в календаре. В календаре, как и при поиске, выбранная дата не ограничивает результат: показываются все совпадения под заголовком «Совпадения по всем датам».
5. Фильтр сохраняется при нажатии «Обновить» и при смене режима «Список»/«Календарь», сбрасывается при перезагрузке страницы, как поиск. Persistent storage не используется.
6. При активном фильтре или поиске показывается `Совпадений: N`. Если совпадений нет — `Ничего не найдено`. Диапазон календаря вычисляется по всем загруженным встречам, как при поиске.
7. Фильтрация идёт по `meetingTypeId`, отображение — `meetingTypeTitle`. Типы с одинаковыми названиями не объединяются.
8. Крайний случай: если после «Обновить» у выбранного типа не осталось встреч, тип остаётся выбранным и показывается пустой результат. Такой выбранный тип остаётся в `data` доступным для удаления, чтобы крестик у пилюли работал; недоступными показываются только невыбранные типы без встреч.
